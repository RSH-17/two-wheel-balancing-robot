# 두 바퀴 밸런싱 로봇 작업 기록

라즈베리파이4 + Cytron MDD3A + JGB37-520 (엔코더 없음) + MPU6050

## 배선

| 장치 | 핀 |
|---|---|
| 모터 1 (M1A / M1B) | GPIO18 / GPIO19 |
| 모터 2 (M2A / M2B) | GPIO12 / GPIO13 |
| MPU6050 VCC | 3.3V |
| MPU6050 GND | GND |
| MPU6050 SDA | GPIO2 |
| MPU6050 SCL | GPIO3 |

## 파일 구성

### `control.py`
전체 밸런싱 로봇 제어 코드. 세 가지 모드 제공.
```
python3 control.py motor   # 1단계: 바퀴 회전 방향 확인
python3 control.py axis    # 2단계: 센서 축과 각도 부호 확인
python3 control.py run     # 3단계: PID 밸런싱 시작
```
- `MPU6050` 클래스: 가속도/자이로 읽기, 상보 필터(ALPHA=0.98)로 각도 추정
- `Motor` 클래스: MDD3A 듀얼 PWM 채널 제어
- `run_balance()`: PID 제어로 실제 밸런싱 수행

### `read_gyro.py`
모터 없이 MPU6050의 자이로/가속도 원시값만 출력하는 테스트 스크립트.
```
python3 read_gyro.py
```
자이로 x/y/z(deg/s), 가속도 x/y/z(g), 온도를 10Hz로 출력.

### `drive_motor.py`
자이로 없이 모터만 구동하는 테스트 스크립트.
```
python3 drive_motor.py                       # 기본 시퀀스 (모터1 -> 모터2 -> 둘 다)
python3 drive_motor.py --speed 0.5 --duration 2
python3 drive_motor.py --motor 1 --speed -0.3 # 모터 1만 구동
```

### `gyro_motor_control.py`
자이로 값으로 모터를 구동하는 naive 제어 테스트 (PID 아님).
```
python3 gyro_motor_control.py            # 기본 게인 0.02
python3 gyro_motor_control.py --gain 0.03
```
- 자이로 Y축 각속도(deg/s)에 게인만 곱해서 `clamp(-1, 1)` 후 두 모터에 동일하게 출력
- 시작 시 가만히 둔 상태로 자이로 오프셋(드리프트) 보정
- 적분/미분 없음, 실제 밸런싱용이 아니라 "기울이면 모터가 반응하는지" 확인용

## 트러블슈팅 기록

### MPU6050 I2C 통신 에러 (`OSError: [Errno 5] Input/output error`)
자이로 센서 초기화(`write_byte_data`) 중 발생. I2C 버스에 장치가 응답하지 않을 때 나는 에러.

확인 순서:
1. `sudo i2cdetect -y 1` → `68`(또는 `69`) 주소가 보이는지 확인
2. `sudo raspi-config` → Interface Options → I2C 활성화 여부 확인
3. 배선 재확인 (특히 점퍼선 헐거움 — 가장 흔한 원인)
4. 클럭 스트레칭 버그 대응: `/boot/firmware/config.txt`에 `dtparam=i2c_baudrate=50000` 추가 후 재부팅

→ 이 세션에서 **해결 확인됨** (사용자 확인: "확인됐어")

### 정지 상태에서 자이로 값이 계속 바뀌는 현상
`read_gyro.py` 실행 시 센서를 가만히 둬도 값이 고정되지 않음. 원인은 두 가지가 섞인 것으로, 둘 다 **정상**.

**1. 0이 아닌 고정 치우침 = 영점 바이어스(offset)**

측정값 x≈+0.60, y≈-0.29, z≈-0.59 deg/s 처럼 일정하게 쏠린 부분. 부품 자체의 특성이라 소프트웨어로 빼주는 것이 정상적인 사용법.
`gyro_motor_control.py`의 `calibrate()`와 `control.py`의 `calibrate()`가 정지 상태 평균을 구해 `gyro_offset`으로 차감한다.
`read_gyro.py`는 보정 없이 원시값만 찍는 테스트 스크립트라 바이어스가 그대로 보이는 것.

**2. ±0.05 수준의 미세한 떨림 = 양자화 + 열 노이즈**

±500 deg/s 레인지에서 1 LSB = 1/65.5 ≈ 0.0153 deg/s. 관측된 변동폭을 LSB로 환산하면 축별로 7~10 LSB, 즉 마지막 몇 비트만 흔들리는 수준. 제거 불가능하고 제거할 필요도 없음.

**데이터시트 대비 측정값**

| 항목 | 측정값 | MPU6050 스펙 |
|---|---|---|
| 자이로 영점 바이어스 | 0.2 ~ 0.6 deg/s | ±20 deg/s (초기 공차) |
| 자이로 노이즈 | p-p 0.1 ~ 0.15 deg/s | 0.05 deg/s-rms (≈ p-p 0.3) |
| 가속도 z 오차 | -0.036 g (0.964 측정) | ±0.08 g (zero-g offset) |

→ 바이어스는 허용치의 약 3%, 노이즈는 스펙의 절반 정도. **정상 범주로 확인됨.**

### 자이로 이상 신호 판단 기준
가만히 둔 상태에서 아래가 나오면 문제를 의심한다.

| 증상 | 의심 원인 |
|---|---|
| 떨림이 p-p 1~2 deg/s 이상 | 전원 노이즈(PWM 모터와 레일 공유), 긴 점퍼선, I2C 풀업 부실 |
| 값이 한 방향으로 서서히 밀림 | 온도 안정화 전. 전원 투입 후 1~2분 뒤 `calibrate()` |
| 0으로 고정 또는 ±레인지 끝값으로 튐 | 결선 또는 레지스터 설정 문제 |
| `sqrt(ax^2+ay^2+az^2)`가 1 g에서 크게 벗어남 | 가속도계 스케일/오프셋 이상 |

주의할 점:
- 모터를 돌리기 시작하면 떨림이 커지는지 반드시 재확인. 위 측정은 모터 정지 상태라 깨끗하게 나온 것.
- 바이어스는 온도에 따라 변하므로(로그에서도 26.1↔26.2 C 왕복) 캘리브레이션 값을 파일에 저장해 재사용하지 말고 **매 실행 시작 때 다시 측정**한다. 현재 코드 방식이 맞음.
- `calibrate()` 도는 동안 로봇이 움직이면 바이어스가 잘못 잡힌다. 손으로 잡거나 흔들리는 상태로 시작하지 않도록 주의.
- 밸런싱에서 실제로 문제가 되는 것은 노이즈가 아니라 바이어스. 0.6 deg/s면 순수 적분 시 1분에 36도가 밀리므로, `control.py`의 상보 필터(`control.py:191`)로 가속도계와 묶어 저주파 드리프트를 잡아주는 구조가 필요하다.
